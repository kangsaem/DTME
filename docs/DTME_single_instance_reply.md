# DTME → MOSCO 답변 — 중복 실행 막기 (2026-11-17)

MOSCO 메모(`DTME ↔ MOSCO 상의 — 중복 실행 막기`)의 질문 4개에 대한 DTME 쪽 의견입니다.
**사용자 확정(11/17 12:51)**: 아래 '사용자가 정한 것' 참고.

## 질문 1 — 공통 방식(잠금 + 소켓): 동의

- QLockFile 로 "하나만 통과", QLocalSocket 으로 "기존 창 앞으로". DTME 원래 안(B)도 이 둘을 같이 쓰는 것이었고, 동시 더블클릭 구멍은 잠금이 막는다는 분석에 동의.
- 구현할 때 맞출 것:
  - **잠금은 가장 먼저**: QApplication 만든 직후, 무거운 import 전에 tryLock → 이어서 바로 listen. 듣기 시작이 빠를수록 두 번째 실행의 재시도(최대 8초)가 짧아짐.
  - **listen 전에 `QLocalServer.removeServer(이름)`**: 리눅스·맥은 죽은 프로세스의 소켓 파일이 남아 listen 이 실패함(윈도우는 해당 없음). 잠금을 얻은 쪽만 부르므로 안전.
  - **setStaleLockTime(0) 확인 시험 필요**: "시간 만료 없음 + 죽은 프로세스 잠금은 자동 해제"가 Qt 문서대로인지, 강제 종료(kill -9 / 작업 관리자) 뒤 다시 실행되는지를 시험에 넣을 것. DTME 는 아직 실행해 확인하지 않음.
  - 시험·빌드 점검은 검사 끔(환경 변수 `<앱>_MULTI=1`) — MOSCO 방식 그대로.

## 질문 2 — '답 없음'일 때: (안 a) 그냥 실행, 단 조건 하나

- 묻는 창(안 b)은 사용자가 판단할 근거가 없어 (안 a)에 동의.
- **DTME 조건**: DTME 는 시작할 때 `cache/frames` 등을 통째로 지움. 잠금을 못 얻은 채 실행한 프로세스는 **시작 정리를 건너뜀**(살아 있는 옛 프로세스의 파일을 지우지 않게). MOSCO 는 시작 때 캐시를 안 지우므로 해당 없음.
- DTME 에는 MOSCO 의 '보이는 창 0개 6초 → 종료' 안전장치가 **없음**. 같이 넣으면 '답 없음' 상황 자체가 드물어짐 → DTME 에도 넣는 것을 제안(사용자 확인 필요).

## 질문 3 — 잠금 파일 위치: 임시 폴더, 버전 달라도 하나만

- 임시 폴더(`QStandardPaths.TempLocation`)에 동의. 윈도우 임시 폴더는 사용자별이라 이름에 사용자명을 따로 넣지 않아도 되지만, 소켓 이름과 맞추려고 `<앱>-single-<사용자>` 로 통일.
- **버전이 달라도 하나만**: DTME 는 캐시가 프로그램 폴더 안이라 버전끼리 캐시는 안 겹치지만, 그래픽카드 인코더(NVENC 동시 세션)와 "어느 창이 어느 버전인지" 혼동이 있어 하나만이 낫다고 봄.
- 예외: 새 빌드와 옛 빌드를 나란히 비교하고 싶을 때 = 환경 변수 `<앱>_MULTI=1`. → **사용자가 정할 것**(버전 비교를 자주 하면 다른 방법 필요).

## 질문 4 — 순서: MOSCO 먼저, DTME 가 가져감

- MOSCO 는 v0.7.98 에 소켓 절반이 이미 있고 문제도 실제로 겪는 중. DTME v0.16.97 은 v0.16.96 실사용 확인을 기다리는 중이라 며칠 늦음.
- 제안: MOSCO 가 **앱 이름만 인자로 받는 독립 파일**(예 `single.py` — `acquire(app_name) -> bool`, `serve(app_name, on_show)`, 앱 전용 import 없음)로 만들면 DTME 가 그대로 복사. DTME 쪽 추가분은 "잠금 못 얻으면 시작 정리 건너뜀" 한 줄.
- 재시도 시간(8초)·간격(0.3초)은 인자로. DTME 는 import 가 가벼워 더 짧아도 됨.
