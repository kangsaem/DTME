# 개인 앱 허브 + 배포·복제방지 (kangyonz.com)

이 문서는 DTME 코드와 별개인 **"배포·도메인·앱 소개 페이지"** 주제의 이어가기 기준이다.
(2026-11-09 대화에서 분리. DTME 코드 자체는 `HANDOFF.md` 기준, 현재 v0.16.22.)

## 1. 하려는 것
- `kangyonz.com` = **개인 개발 앱들을 나열하는 소개 페이지**(허브). 다이빙 국한 아님. 앱 예: DTME(다이빙 영상 편집), 머니파이, V1 리포트 등.
- 각 앱은 서브도메인으로: `dtme.kangyonz.com` 처럼. (허브가 루트, 앱은 서브)
- DTME 등은 나중에 **영어 버전**(버튼·메뉴)도 만들 계획.

## 2. 도메인 — 결정
- `www.kangyonz.com` 이미 소유 → 서브도메인은 **무료, 개수 제한 없음**. 단 자동 아님: 서브마다 DNS 레코드 1줄 + HTTPS 인증서 + 역방향 프록시 설정 필요.
- 와일드카드 인증서 `*.kangyonz.com` 하나 받아두면 앞으로 만들 모든 서브도메인에 재사용.
- 결정: 허브 = `kangyonz.com`, DTME = `dtme.kangyonz.com`.
  - 서브도메인(하위경로 `/dtme` 아님) 선택 이유: 시놀로지 역방향 프록시가 서브도메인 단위로 쉬움, 로그인 쿠키 분리(보안), 인증서·이전 독립.
  - `.kr`(yonz.kr)은 외국인에게 "한국 전용" 느낌 + `.com` 오타 위험 → 영어화 계획 있으므로 `.com` 유지.
  - 제품으로 크게 키울 때만 `dtme.app` 등 단독 도메인으로 이전 고려(서브도메인으로 시작했으면 이전 쉬움). 지금은 불필요.

## 3. 복제 방지 — 현실 정리 (중요)
- **exe 배포 = 완벽 방지 불가.** PyInstaller exe 는 풀면 코드 가까이 나옴. 라이선스 코드도 제거 가능.
- 목표를 "작정한 전문가 차단"이 아니라 **"exe 가 통제 없이 퍼지는 것 방지"**로 잡는 게 현실적.
- 방식:
  - **A. NAS에서 받아 실행 후 삭제**: 실행 순간 빼낼 수 있어 약함.
  - **B. 서버 인증 받아야 실행 (추천, 가벼움)**: 계정·기기 확인. 난독화(PyArmor)/컴파일(Nuitka) 병행. 보통 사용자에겐 충분, 기술자에겐 뚫림.
  - **C. 핵심(AUTO 분석·추천·프리셋)만 서버**: 코드 복사엔 강하지만, **보정값이 에디터 화면에 다 보이므로 "결과를 모아 흉내"는 못 막음**(사용자 지적 반영). 노력 대비 효과 제한적.
- **NAS CPU 로는 4K 처리 안 함**(저전력·GPU 없음, 일반 시놀로지는 GPU 미지원). 무거운 작업은 사용자 PC(NVIDIA). NAS 는 인증·작은 계산·소개 페이지 호스팅만.
- 라이선스(법률조언 아님): 현재 빌드의 FFmpeg = GPL → **exe 배포 시** FFmpeg 부분 소스공개 의무 가능. 서버 실행+결과만 제공은 보통 배포로 안 봄. Qt(PySide6)=LGPL 조건. DJI LUT 동봉 배포 가부 확인 필요. 실제 배포·판매 전 전문가 확인 권장.

## 4. 다음 할 일 (새 대화 시작점)
1. **허브 페이지 만들기**: `kangyonz.com` 에 앱 목록(이름·한 줄 설명·링크·상태). 정적 페이지면 충분. → 만들 때 산출물 형식(단일 HTML 아티팩트 등) 상의.
2. **시놀로지 설정**: `dtme.kangyonz.com` DNS + DDNS/Cloudflare Tunnel + 와일드카드 인증서 + 역방향 프록시. (www 가 이미 되면 틀은 있음.)
3. **DTME 배포 방식 확정**: B(서버 인증)로 시작할지. 쓸 사람 수·관계(아는 사이 여부)·NAS 모델/DSM 버전 확인 후.
4. (선택) 영어 버전 UI.

## 5. 미결·확인 필요
- 쓸 사람 규모·관계(인증 강도 결정).
- 시놀로지 모델명·DSM 버전.
- DTME 를 실제로 남에게 줄 계획인지(배포/판매) → 라이선스 영향.
