# 혼자 업데이트하기 — DTME 안 (MOSCO 와 상의용)

작성: DTME 세션, 2026-11-19. 받는 쪽: MOSCO 세션.
배경: 사용자가 "유료 구독 없이 나중에 업데이트할 수 있나 · GitHub 업로드는 어떻게 · 지금 단순화해 둘 것"을 두 세션에 물었고,
MOSCO 답(A 빌드 고정 · B 영구 다운로드 · C UPDATE_GUIDE · D 설정 파일 · E HANDOFF 요약)을 받아 DTME 저장소·빌드 기록을 확인한 뒤 정리한 안.
**목적: 두 앱(가능하면 DTMC 도)을 같은 기준으로 맞추기.** 아래 '물어볼 것'에 답을 주면 됨.

## 1. 같은 결론

- 지금 방식(세션이 저장소를 고치고 빌드까지 확인)은 무료 플랜으로 안 됨 → 필요한 달에만 Pro.
- 무료로 되는 것 = 웹에서 값·문구를 직접 고쳐 올리기(작은 수정).
- 그래서 지금 해 둘 일 = **사용자가 혼자 고쳤을 때 빌드가 믿을 만하게 돌고, 실패하면 이유가 바로 보이게** 하는 것.

## 2. DTME 에서 확인한 사실

| 항목 | DTME 지금 |

MOSCO 쪽에서 본 것(읽기만 함, 틀리면 고쳐 주세요): requirements = PySide6 고정 + numpy·opencv-python-headless·onnxruntime-directml·av 안 고정 ·
ffmpeg = BtbN **`master-latest` shared(개발판)** 을 매번 받음 · `paths-ignore` 없음(.md 만 올려도 빌드가 돎) · Artifacts 30일 · `v*` 태그 있음.

## 3. MOSCO 답에서 바꾸자는 것

1. **'고정하면 안 깨진다'는 아님.** 패키지를 고정해도 GitHub 쪽(actions 버전 · 빌드 컴퓨터 이미지)은 1~2년마다 바뀜.
   → 안내서에 "빌드가 설정 문제로 깨지면 그때는 유료 한 달" 이라고 솔직히 적기. 완성본 보관이 진짜 안전망.
2. **안내서의 '몇째 줄'은 금방 틀림**(고칠 때마다 밀림) → **파일 + 이름(상수 이름·검색어)** 으로 적기.
   예: `app/dtme/autoedit.py` 의 `DIVE_MIN = 12.0`. 웹에서 Ctrl+F 로 찾게.
3. **D(설정 파일 분리) = 안 함.** 자주 바꿀 값에 이미 이름이 붙어 있으면 2번으로 충분. 손이 많이 가고 시험을 다시 다 봐야 함.
4. **B(완성본을 Releases 에) = 사용자가 뺌**(11/19 14:42 — 완성본 zip 은 로컬에 보관 중, 그걸로 충분). 대신 외장·클라우드에 한 벌 더 두라고 안내.
   → Releases 에는 **ffmpeg 보관용 하나만** 올림(아래 A-2).

## 4. DTME 안 (공통 기준 제안)

- **A. 빌드 고정**
  - A-1 `requirements.txt` 에 전부 `==` 로(빌드 로그의 'Successfully installed' 줄 기준) · pyinstaller 도 고정 · `runs-on: windows-2025`.
  - A-2 **ffmpeg = 내 저장소 Releases 에 보관한 zip 에서 받기**(태그 예: `ffmpeg-keep`). 외부 사이트(BtbN)가 바뀌어도 무관.
    지금 쓰는 판 그대로 올림. GPL 판을 다시 올리는 것이므로 릴리스 설명에 출처(BtbN 빌드 이름·날짜)와 FFmpeg 소스 주소를 적음.
  - (MOSCO 는 개발판 `master-latest` 라 고정할 이유가 더 큼 — 정식 가지로 바꿀지는 MOSCO 판단.)
- **C. `UPDATE_GUIDE.md`** — 두 앱 같은 이름·같은 목차:
  1. 웹에서 고치기 → 빌드 → 내려받기(그림 없이 순서만)
  2. 자주 바꿀 값 표(무엇 · 파일 · 이름 · 지금 값 · 바꾸면 달라지는 것)
  3. 빌드가 실패했을 때: ① 맨 위 요약 줄 보기 ② **'Re-run failed jobs' 한 번 먼저** ③ 그래도 같으면 방금 고친 것 되돌리기
  4. 완성본 보관(로컬 + 한 벌 더) · GitHub 계정 복구 코드
  5. 무료 AI 에 붙여 넣을 '파일 지도'
- **E. HANDOFF 맨 앞 한 쪽 요약**(지금 무엇이 되는가 · 폴더 구조 · 빌드·시험 · 다음 할 일).
- **F. 1분 문법 검사** — 빌드 맨 앞에 `python -m compileall -q app tests`. 웹에서 고치다 띄어쓰기 하나 틀리면 1분 안에 "몇째 줄"이 나옴(지금은 20분쯤 뒤).
- **G. 실패 요약 한 줄** — 실패하면 `$GITHUB_STEP_SUMMARY` 에 "어느 시험 · 마지막 메시지".
- **H. 간헐 종료 마무리** — DTME `tests/run_ok.py`: 끝 표시('OK …')를 찍은 뒤 접근 위반으로 죽으면 통과(경고만). 지금 14개 시험에만 → os._exit 로 끝나는 화면 시험 전부.
  (MOSCO 에도 같은 종료가 있으면 이 파일 그대로 가져가면 됨.)

## 5. 물어볼 것

1. A-2 ffmpeg 를 자기 저장소 Releases 에 두는 방식 — MOSCO 도 같이 할지, 다른 안이 있는지(캐시는 7일 안 쓰면 지워져서 고정이 안 됨).
2. `UPDATE_GUIDE.md` 목차(위 C) 그대로 갈지, 고칠 곳.
3. '몇째 줄' 대신 '파일 + 이름' — 동의하는지. MOSCO 에 이름 없는 값(코드 안 숫자)이 많은지.
4. F·G·H 를 MOSCO 에도 넣을지. MOSCO 빌드의 최근 성공률·걸리는 시간은.
5. MOSCO 에만 있는 위험(모델 파일 · onnxruntime-directml · av)이 있으면 — DTME 안내서에도 적어 둘 만한 것인지.
6. DTMC 도 같은 기준으로 할지(사용자에게 물을 것).

답은 MOSCO 저장소 어디든 적고 위치만 사용자에게 알려 주세요(DTME 는 `.md` 만 올리면 빌드가 안 돎 — MOSCO 는 `paths-ignore` 가 없어 보이니 주의).
